# QZDB 多语言 SDK 标准测试与验证规范  
**（Test & Verification Specification · Full Edition · Dual-Stack Compatible）**

**版本**：v2.1（IPv4 + IPv6 完整兼容）  
**适用范围**：Java / C# / Go / Rust / Python / Node.js / PHP / C 等全部官方与社区 SDK  
**核心原则**：  
1. **Fail-Closed** 优先于性能  
2. **Ground Truth 零偏差** 优先于速度  
3. **真实分布 + 双栈均衡压测** 优先于硬编码 IP  
4. **跨语言公平对比** 优先于单语言优化  
5. **IPv4 / IPv6 / IPv4-Mapped 全链路对称测试**，严禁只测 IPv4

所有语言 SDK 的开发、重构、Code Review 与发布必须严格执行本规范的**三层递进验证**。严禁仅用少量硬编码 IP 敷衍交差。

---

## 一、三层验证体系总览

```
Tier 1  →  纯逻辑 + 边界防御 + 安全 Fail-Closed（单元级，必须 100% 通过）
Tier 2  →  地面真值全量/抽样逐字段比对（准确性，0 偏差）
Tier 3  →  高并发无锁 + 性能基准（可扩展性与延迟，双栈均衡）
```

**执行顺序强制**：Tier 1 全绿后才允许跑 Tier 2；Tier 2 0 偏差后才允许正式性能报告。

---

## 二、Tier 1：纯逻辑与单元边界测试（Unit & Boundary Defense）

**最低要求**：≥ 50 项独立断言，覆盖以下 **9 大核心分类**。所有断言必须在**无真实数据库文件**或**最小伪造文件**下即可独立运行。

### 1. 严格 IP 解析与格式规范（Strict IP Parsing · Dual-Stack）

#### 1.1 IPv4 严格性
- **合法**：`0.0.0.0`、`255.255.255.255`、`1.2.3.4`、`192.168.0.1`、`223.5.5.5`
- **必须拒绝**（返回 `ErrorCode.INVALID_IP`）：
  - 前导零：`01.1.1.1`、`1.02.3.4`、`1.1.1.01`
  - 越界：`256.1.1.1`、`1.1.1.256`、`1.300.1.1`
  - 缺段：`1.1.1`、`1.1`、`1`
  - 超段：`1.1.1.1.1`
  - 非数字、空串、纯空格、超长（≥10,000 字符）
  - 带端口：`1.1.1.1:80`
  - CIDR 形式：`1.1.1.1/24`
  - 带掩码或特殊字符

#### 1.2 IPv6 规范性
- **合法双冒号压缩**与 **8 组全展开**必须解析为**字节级完全一致**：
  - `2001:db8::1` ≡ `2001:0db8:0000:0000:0000:0000:0000:0001`
  - `::1` ≡ `0000:0000:0000:0000:0000:0000:0000:0001`
  - `2001:218::` ≡ `2001:0218:0000:0000:0000:0000:0000:0000`
- **必须拒绝**：
  - Scope/Zone ID：`fe80::1%eth0`、`fe80::1%1`
  - 多余冒号、非法十六进制、混合非法形式
  - 超过 8 组、少于合法压缩规则
  - 带端口或 CIDR 形式（除非明确支持并单独测试）

#### 1.3 IPv4-Mapped IPv6 自动降级（强制）
- `::ffff:223.5.5.5` 与十六进制形态 `::ffff:df05:0505` **必须自动剥离前缀**，解出与 `223.5.5.5` **100% 相同**的结果（所有字段一致）
- 其他合法 Mapped 形式同理
- 非法 Mapped（如 `::ffff:256.1.1.1`）必须拒绝

#### 1.4 混合与边界
- 纯 IPv4、纯 IPv6、Mapped 三种输入路径结果必须一致（当语义相同时）
- 空串、纯空格、超长垃圾串统一返回 `INVALID_IP`，严禁死循环或内存越界

### 2. 字段名归一化与 Getter 大小写/下划线不敏感

- 校验：
  ```
  info.get("country_code") == info.get("countryCode") == 
  info.get("COUNTRY_CODE") == info.get("CountryCode") == 
  info.get("country-code") == info.get("Country_Code")
  ```
- 归一化规则：**转小写 + 去除下划线/连字符**
- 未匹配字段必须安全返回空字符串 `""`（或 `null`/`None`/`Option::None`），**严禁抛出 KeyError / 索引越界 / Panic**

### 3. UsageType 21 场景官方映射与未知类型兜底

- 完整覆盖官方 21 种场景（CDN、Cloud、Broadband、AICrawler、Hosting、ISP、Mobile、Education、Government、Enterprise 等）
- 校验 `display_zh` / `display_en` / `description` 正确解析
- 传入未来未知场景字符串（如 `FutureUnknownType`、空、乱码）时：
  - `isKnown() == false`
  - 原样返回原始字符串
  - 不崩溃、不抛异常

### 4. 恶意输入与伪造/损坏文件安全防御（Fail-Closed）

- **恶意字符串攻击**：超长（≥10,000 字符）、带掩码 CIDR、空串、纯空格、特殊控制字符 → 优雅返回 `ErrorCode.INVALID_IP`，**严禁死循环、无限递归、内存爆炸**
- **损坏二进制文件**：
  - 伪造 Magic（非 `QZDB`）
  - 截断短文件（<192 字节 Header）
  - 损坏偏移量的非法字节流
  - → 构造函数必须 **Fail-Closed 拒绝初始化**，抛出 `ErrorCode.BAD_MAGIC` / `BAD_HEADER` / `CORRUPTED`
- 禁止部分加载或静默降级

### 5. CRC32 全文件流式校验与 Fail-Closed

- 破坏文件第 200 字节（或其他任意位置）后加载，`verifyCrc=true` 必须拒绝加载并抛出校验失败异常
- **严禁 `crc == 0` 盲目放行**
- 支持流式校验（大文件不整文件读入内存）

### 6. 无锁热重载（Reload）与原子切换

- 运行 `reader.reload(newFile)` 时，后台 ≥16 线程/协程并发查询：**零锁冲突、零脏读、零 NPE/Panic/Segfault**
- 当 `reload(junkFile)` 失败时，**旧快照必须继续正常服务**（影子替换失败不毁坏现有连接）
- 验证原子指针/引用切换语义（语言相关：AtomicReference / ArcSwap / volatile 等）

### 7. CIDR 网段反查 API（lookupCidr / lookupCidrBytes）· 双栈

- **IPv4**：`lookupCidr("223.5.5.5")` 准确返回最具体网段（示例：`223.5.0.0/17`，以实际库为准）
- **IPv6**：`lookupCidr("2001:218::1")` 准确返回对应最具体网段（示例：`2001:218::/32`）
- **IPv4-Mapped**：输入 Mapped 形式时，结果应与剥离后的 IPv4 一致
- 跳表直中叶子节点时，必须自动从 Trie 根部补走还原深度
- 未命中返回空/None；非法 IP 返回错误码

### 8. 多字节序 / 平台兼容性与资源释放

- 大端/小端机器加载同一 `.qzdb` 文件结果完全一致
- 显式 `close()` / `Drop` / `dispose` / `free` 后再次查询必须安全失败（不 UAF、不 double-free）
- 多次 `getInstance` / 单例行为符合各语言规范
- 文件句柄与 mmap 正确释放

### 9. 双栈一致性交叉断言（新增强制）

同一语义 IP 的三种输入形式结果必须字段级一致：
- `223.5.5.5`
- `::ffff:223.5.5.5`
- `::ffff:df05:0505`

任意字段不一致即判定失败。

**Tier 1 合格标准**：所有断言全绿；核心解析路径语句/分支覆盖率建议 ≥ 90%。

## 三、Tier 2：地面真值全量/抽样逐行比对（Ground Truth Cross-Verification）

此阶段是验证 SDK 解析代码**真实准确性与零幻觉**的最关键关卡。

### 1. 测试数据源标准（必须覆盖）

使用仓库最新 `test_data_YYYYMM` 或官方商业库的 **10 大全规格版本**：

| 序号 | 版本 | 文件示例 |
|------|------|----------|
| 1 | std/china | qqzeng_ip_std_china.qzdb + 对应 CSV |
| 2 | std/global | qqzeng_ip_std_global.qzdb + 对应 CSV |
| 3 | pro/china | qqzeng_ip_pro_china.qzdb + 对应 CSV |
| 4 | pro/global | qqzeng_ip_pro_global.qzdb + 对应 CSV |
| 5 | ult/china | qqzeng_ip_ult_china.qzdb + 对应 CSV |
| 6 | ult/global | qqzeng_ip_ult_global.qzdb + 对应 CSV |
| 7 | asn/china | qqzeng_ip_asn_china.qzdb + 对应 CSV |
| 8 | asn/global | qqzeng_ip_asn_global.qzdb + 对应 CSV |
| 9 | max/china | qqzeng_ip_max_china.qzdb + 对应 CSV |
| 10 | max/global | qqzeng_ip_max_global.qzdb + 对应 CSV |

CSV 必须同时包含 **IPv4 与 IPv6** 网段数据（若某版本仅有其一，需在报告中明确说明）。

### 2. 比对采样规则（强化版）

- **输入**：CSV 每一行的 `start_ip`（或 CIDR 代表 IP）+ 可选 `end_ip` 中点采样
- **输出**：SDK `find(ip)` 返回的全部字段（6~25 维）与 CSV 期望值**逐字段、逐字符**比对
- **采样策略**（推荐组合，兼顾覆盖与速度）：
  1. **全量**（小库 / CI 夜间 / Release）：所有节点
  2. **分层抽样**（日常）：按 A 段/前缀均匀 + 热门段加密 + 边界网段必测
  3. **随机百万级**（快速回归）：固定种子可复现
- **双栈要求**：IPv4 与 IPv6 节点必须分别统计通过率，最终总偏差为 0
- **合格标准**：累计校验节点 ≥ **39,000,000**（或全量），**偏差必须为 0（100% 精确对齐）**

### 3. 规范排除项说明（必须显式声明）

依据 `QZDB_SDK_API.md` §9.7：
- `::ffff:0:0/96` 等 5 条 IPv4-mapped IPv6 网段行在 V6 Trie 中有保留行，但规范强制剥离前缀走 V4 Trie
- 测试器中对此 5 条特定边界行需做**显式白名单排除**，并在报告中注明排除数量与原因
- 其余全量行必须 100% 对齐

### 4. 报告要求

必须输出：
- 机器可读差异文件（JSON/CSV）
- 人类可读汇总：总节点数、IPv4 节点数、IPv6 节点数、匹配数、偏差数、排除数、耗时
- 首 20 条差异详情（IP + 字段名 + expected vs actual）

## 四、Tier 3：高并发锁安全与性能压测（Benchmark & Concurrency · Dual-Stack）

### 1. 压测样例生成与公平全覆盖机制（严禁硬编码）

为了保证跨语言压测的**绝对公平、真实、全面与防 CPU 缓存欺骗**，压测 IP **严禁使用任何固定的三五个 IP 硬编码数组**！必须使用以下动态生成算法之一（推荐 **A + C 组合**）：

#### 方案 A：从真实数据库随机全网段平滑散列采样（全分布覆盖 · 推荐）
- 原理：在压测初始化阶段，使用随机种子或按特定步长遍历全网 256 个 `/8` A 段，生成包含 **≥1,000,000 个随机真实 IP 预热池/循环队列**（覆盖冷热节点、叶子节点与跳表命中节点）
- 算法示例（伪代码）：
  ```python
  # 动态步长取模，覆盖 A/B/C/D 段全网段，防 CPU 分支预测缓存欺骗
  ip_str = f"{(i % 255) + 1}.{((i * 17) % 256)}.{((i * 131) % 256)}.{(i % 254) + 1}"
  ```

#### 方案 B：真实 CSV 地面真值数据全量全覆盖热跑
- 直接将 Ground Truth CSV 中的前 100 万条 `start_ip`（含 IPv4 + IPv6）加载为压测输入数组，模拟真实生产网段访问分布

#### 方案 C：双栈协议 1:1 均衡压测（50% IPv4 + 50% IPv6 · 强烈推荐）
- **比例划分**：**50% 动态 IPv4 + 50% 动态 IPv6**
  - 其中 IPv6 内部再细分：40% 纯 IPv6（双冒号压缩 / 8 组全展开多态）+ 10% IPv4-Mapped
- 确保 IPv4 与 IPv6 两棵检索树得到 **1:1 充分、公正的极限吞吐压测**
- 动态 IPv6 生成算法示例（伪代码）：
  ```python
  g1 = f"{((i * 31) % 0xFFFF):04x}"
  g2 = f"{((i * 17) % 0xFFFF):04x}"
  g3 = f"{((i * 131) % 0xFFFF):04x}"
  if i % 5 == 0:
      v6_str = f"2001:{g1}:{g2}::{g3}"               # 双冒号压缩
  elif i % 5 == 1:
      v6_str = f"2001:{g1}:0000:0000:{g2}:0000:0000:{g3}"  # 8组全展开
  else:
      v6_str = f"::ffff:{(i%255)+1}.{((i*17)%256)}.{((i*131)%256)}.{(i%254)+1}"  # Mapped
  ```

**所有生成必须固定随机种子**，保证跨语言、跨机器可复现。

### 2. 线程/协程并发安全测试

- **最低配置**：至少 **16 线程/协程 × 100,000 次** 高频随机并发查询（输入必须双栈混合）
- **校验点**：
  - 全程无数据竞争（Data Race Free）
  - 无 `NullPointerException` / `Panic` / `Segmentation Fault`
  - 返回数据格式合法
- 建议使用语言原生 race detector（Go `-race`、Rust ThreadSanitizer、Java Concurrent 工具等）

### 3. 性能评估与基准对齐

压测必须使用选定的全量库（推荐 `max/global/qqzeng_ip_max_global.qzdb`），进行预热后测试：

| 指标 | 目标参考（可根据硬件调整） | 必须报告 |
|------|---------------------------|----------|
| 单线程 QPS | 1.5M ~ 6M+ | ✓ |
| 单次延迟（P50/P99） | < 1 µs | ✓ |
| 4/8/16 线程 QPS | 接近线性扩展，16 线程 10M~35M+ | ✓ |
| 内存/分配 | 趋近 Zero Allocation（查询路径） | ✓ |
| IPv4 vs IPv6 分别 QPS | 必须分开统计 | ✓ |
| 预热前后对比 | 必须有 | ✓ |

**公平性强制要求**：
- 相同硬件、相同编译优化级别、相同预热次数
- 禁止在压测循环内做字符串格式化/日志等额外开销
- 报告必须包含：CPU 型号、核心数、内存、OS、语言版本、编译参数、随机种子

### 4. 额外建议压测场景

- 热重载过程中的并发查询稳定性（双栈混合）
- 长时间运行（≥ 10 分钟）无内存泄漏
- 不同数据库版本（std → max）的性能衰减曲线
- IPv4-only / IPv6-only / Mapped-only 单独压测对比

## 六、额外专业落地建议（强烈推荐）

1. **CI 集成分层**  
   - PR：Tier 1 全量 + Tier 2 快速抽样（≥1M 节点，含 IPv4/IPv6）+ 轻量并发  
   - Nightly / Release：全量 Tier 2 + 完整 Tier 3

2. **可复现性**  
   所有随机采样固定种子 + 记录生成算法版本号。

3. **跨语言一致性检查**  
   同一批双栈 IP，用 Python（参考实现）与其他语言结果做二次交叉验证。

4. **性能回归阈值**  
   建立 baseline 文件，QPS 下降 > 10% 或 P99 延迟上升 > 20% 即失败。

5. **错误码统一**  
   所有语言使用同一套 `ErrorCode` 枚举，便于测试器统一断言。

6. **文档化排除与已知限制**  
   任何无法 100% 对齐的边界必须在测试报告与 README 中明确写出。
